# 充电机模拟器（EB90 通用规约）

在没有充电机实物时，用 PC + USB-RS485 模拟充电机（电源模块），和 DTU 做问答测试。

- Python 3.14 + PySide6 6.12
- 只实现**通用 EB90 规约（版本 2 语义）**
- 静态点表 + 手动改值，不做电池模型/自动流程
- 支持装置类型表 XML（GB2312/GB18030）+ 组模板 JSON

## 运行

双击 `run.bat`，或者：

```bat
cd /d E:\充电机\模拟工具
.venv\Scripts\python.exe -m app.main
```

## 界面布局

- **左侧**：数据类型入口（遥测 / 遥信 / 遥控 / 定值）
  - 每类只显示一个入口，点进去在右侧看这一类的**全部点**
  - 下面是节点计数、空节点告警、XML 检查
  - 再下面是**电池模型**和**场景**控制（不再占底部标签）
- **右侧**：当前分类的统一表，首列“组”标明该点来自哪个功能码/子类型
  - 遥测/定值：原始 HEX、原始十进制、系数、工程值
  - 遥信：复选框
  - 遥控：成功/失败下拉
  - XML 没覆盖的字节：自动生成“扩展字段/原始数据”行
  - 顶部“点格式...”可设置有符号/字节序/浮点/偏移/系数
  - 顶部“搜索”按名称/偏移/HEX 过滤行
- **顶部**：“加载 XML...”左边显示当前 XML 文件名（悬停看完整路径）
- **底部标签**：
  - **报文监视**：只显示 `RX / TX / ERR / ECHO` + 原始 HEX（不再显示 addr/func/sub/data）
  - **运行日志**：XML 加载、`WARN`、`FAULT`、`REC`、`SKIP`、串口错误，可导出 TXT
- **菜单**：
  - 文件：加载 XML、保存/加载预设、重置数据、退出
  - 工具：暂停应答、自动重连、点格式、XML 检查、显示高级工具栏

> 故障注入、模板、录制响应默认收在“工具 → 显示高级工具栏”里，主界面只保留核心模拟功能。

XML 加载信息和告警不会再混进报文监视。

## 使用流程

1. 插好 USB-RS485，确认设备管理器里的 COM 口。
2. 选择串口、波特率（默认 9600）、地址（默认 1），点“打开串口”。
3. 点“加载 XML...”，选择装置类型表。
4. 左侧选择“遥测 / 遥信 / 遥控 / 定值”，右侧显示该类的全部点；首列是所属组。
   电池模型/场景也在左侧，启动后**收到 DTU 对应查询时才更新点表**。
5. 直接改值；“自动应答”保持勾选，取消勾选或勾“暂停应答”后只收不发。
6. 底部“报文监视”只显示 `RX/TX/ERR/ECHO`；加载信息和告警看“运行日志”标签。
7. 需要故障注入时，打开“工具 → 显示高级工具栏”，再勾选“不回帧 / 延迟 / 错校验 /
   错地址+1 / 短帧 / 每 N 帧丢 1 帧”。
8. 需要模板/录制时，同样在“显示高级工具栏”里操作。
9. 选中一个遥测/定值点，点“点格式...”设置 `i16be`、`f32be`、偏移、系数等。
10. “文件”菜单可保存/加载预设值；点表上方“搜索”可按名称/偏移/HEX 过滤。
11. 串口异常断开时，勾选“自动重连”会每 2 秒重试；COM 口插拔会自动刷新列表。
12. “场景/电池”标签：启动电池模型或加载场景 JSON，观察 SOC/电压/告警随时间变化。

## 串口与无报文排查

- 这里的“串口”是**电脑上 USB-RS485 适配器对应的 COM 口**，不是 DTU 的调试口。
- 接线：PC 的 USB-RS485 A/B ↔ DTU 电源模块 485 的 A/B；建议共地；长线加 120Ω。
- **必须点“打开串口”**：顶部状态变绿色“串口已打开”，按钮变成“关闭串口”。
- 地址默认 1，必须与 DTU 配置一致；XML 要与 DTU 的装置类型表一致。
- 正常时“报文监视”每 100ms 出现 `RX EB 90 ...`，工具回 `TX EB 90 ...`。
- 没有 RX：选错 COM、A/B 接反、未共地、DTU 没有轮询这个口、驱动未装/端口被占用。
- 没连接充电机时，点表里的值是**模拟器自己的状态**，不代表真实设备；
  要清零先停止电池模型/场景，再点“重置数据”。

## XML 支持

支持以下节点：

| 节点 | 含义 | 映射 |
|---|---|---|
| `MeasureDefine` | 遥测 | `GroupNo`=功能码，`EntryNo`=子类型，`FUN`=起始字节，`INF`=字节长度，`Factor`=系数 |
| `SignalDefine` | 遥信 | `FUN`=字节，`INF`=位号 |
| `ControlDefine` | 遥控 | `GroupNo`/`EntryNo` 即功能码/子类型 |
| `FixValDefine` | 定值 | `FUN`=起始字节，`INF`=字节长度 |
| `SetPointDefine` | 定值（兼容） | 同上 |

每个 `(GroupNo, EntryNo)` 对应一个组，组内维护一个数据区 `bytearray`：

- 它既是点表显示的值，也是回复帧的数据区；
- XML 没有覆盖到的字节就是“扩展字段”，在点表里单独成行，直接改原始值；
- 定值点 `ValueType` 只影响显示，**线上字节长度只按 `INF`**。

> 正常情况下，一个完整的装置类型表应同时包含 `MeasureDefine`、`SignalDefine`、
> `ControlDefine`、`FixValDefine` 全部节点，工具一次加载这一份即可。
> 当前备份里的 `WTJND.xml` 只是定值测试桩（只有 `FixValDefine` 3 点），
> `DMP2219_Pow_CQ1000WTJND.xml` 是完整三遥表但没有定值节点；
> 这是当前开发阶段的文件状态，不是工具要求。**工具不会修改 XML。**
>
> 加载后左侧显示 `遥测 x / 遥信 y / 遥控 z / 定值 w`，以及 ⚠ 空节点提示；
> 运行日志也会打 `WARN`，方便判断为什么 DTU 只轮询某些子类型。

## XML 校验

点左侧“XML 检查...”或“工具 → XML 检查...”，报告以下问题：

- 同一组内数据区重叠
- 遥信同字节/同位重复
- FUN/INF 越界（数据区最长 252 字节）
- 系数为 0
- 数据区为空或过长
- 同一组混合遥测/遥信/定值
- 空节点（没有遥测/遥信/遥控/定值）

只做静态检查，不替代 DTU 侧加载校验。**工具不会修改 XML。**

## 组模板

`data/templates.json` 给没有真实报文的组提供初始数据区：

```json
{
  "0x1B01": "00 18 12 5C 00 28 00 64"
}
```

- 键支持 `0x1B01`、`1B01`、`27/1`（十进制）、`0x1B/0x01`（十六进制）；
- 值是十六进制字节；
- 模板比 XML 点表长的部分就是扩展字段；
- 当前 `0x1B01` 模板含义：24AH、47.00V（原始 4700）、剩余报警 40%、剩余容量 100%。

XML 里若只有 3 个定值点（`FUN=0/2/4`），第 4 个值（`FUN=6`）就从模板里保留，
点表里的“扩展字段”行可以看到并修改。

### 模板管理

打开“工具 → 显示高级工具栏”，点“模板...”打开对话框：

- 表格直接编辑 `组` / `数据区 HEX`；
- “从当前组生成”：把当前组数据区写成模板；
- “从报文导入”：粘贴完整响应帧（`EB 90 ...`），工具按功能码/子类型推导组；
- “从录制导入”：从“录制响应”缓存里选一帧；
- “保存”：只写 `data/templates.json`，下次加载 XML 生效；
- “保存并应用”：写文件并按模板重置所有组（会弹确认，当前手动改的值会丢失）。

**工具不会修改你的装置类型表 XML。**

### 录制真实响应

`0x1A/0x1B/0x83` 的请求和响应功能码相同，工具用以下规则判断“这是响应”：

> 收到请求后 20~280ms 内，同地址、同功能码、同子类型、且数据区非空。

步骤：

1. **取消**“自动应答”（工具只监听，不驱动总线）；
2. 在“显示高级工具栏”里勾选“录制响应”；
3. 让 DTU 正常轮询真实充电机，工具和真实设备挂在同一条 485 上；
4. 运行日志出现 `REC` 后，打开高级工具栏的“模板...” → “从录制导入”；
5. 保存，或保存并应用。

> 如果适配器回声严重，建议换自动方向适配器；录制时工具不应发送任何数据。

## 点格式（有符号/字节序/浮点/偏移）

XML 只有 `Factor`，没有符号、偏移、浮点信息。选中一个遥测/定值点，点“点格式...”：

- 数据类型：`auto` / `u8` / `i8` / `u16be` / `i16be` / `u16le` / `i16le` /
  `u32be` / `i32be` / `u32le` / `i32le` / `f32be` / `f32le` / `raw`
- 偏移：`工程值 = 原始值 × 系数 + 偏移`
- 系数：留空/等于点原系数时沿用 XML `Factor`
- `auto`：按长度 1/2/4 使用 `u8/u16be/u32be`，其余按原始大端
- 类型长度与 `INF` 不一致时禁止保存

保存到 `data/point_formats.json`，按 XML 文件名分组；**不修改 XML**。
点表“说明”列会显示当前格式，例如 `i16 大端 offset=-40`。

## 预设值

“文件”菜单：

- **保存预设**：把所有组数据区存成 JSON（含来源 XML 路径）
- **加载预设**：按组号写回；当前 XML 没有的组跳过并在运行日志提示

适合重复测试用例；默认文件名 `data/preset.json`，可在对话框里改名。

## 报文过滤与导出

报文监视：

- 方向：全部 / RX / TX / ERR / ECHO
- 文本：按 HEX 过滤
- **导出 CSV**：时间、方向、原始帧（只导出当前过滤结果）

运行日志：**导出 TXT**。

## 故障注入

默认收在“工具 → 显示高级工具栏”里。

| 控件 | 行为 |
|---|---|
| 不回帧 | 生成响应但不发送 |
| 延迟 N ms | N 毫秒后再发送；超过 300ms 会触发 DTU 超时重发 |
| 错校验 | 把响应最后一字节（校验和）取反 |
| 错地址+1 | 把响应地址改成 `addr+1`，并重算校验和 |
| 短帧 | 少发最后 1 字节（校验和），DTU 会等待/超时 |
| 每 N 帧丢 1 帧 | 按响应计数，每第 N 帧不发送；0=关闭 |

- 故障只作用于**响应**，不影响请求解析；
- 运行日志会打 `FAULT` 行，说明本次注入了什么；
- “清除故障”会取消所有勾选、清零延迟/丢帧计数；
- 想验证通讯中断，可以直接勾“不回帧”或“每 N 帧丢 1 帧”。

## 串口自动重连

- 勾选“自动重连”：串口异常断开（拔线/驱动错误）后每 2 秒重试
- 等待期间 COM 热插拔不会把选择切到别的口
- COM 口插拔时列表自动刷新（2 秒）
- 手动“关闭串口”不会触发重连

## 场景/电池模型

左侧“电池模型”和“场景”区域。

### 电池模型

- **启动模型 / 停止 / 重置**
- **交流供电**、A/B/C 相失电
- **负载电流**、**充电电流**
- **SOC / 电压 / 状态**实时显示
- **活化启动 / 活化停止**

模型每秒 tick 更新内部 SOC/电压/告警状态，但**只有收到 DTU 对应查询报文时**，
才把状态写进该组点表并回应。启动/重置/改参数时会先清空模型相关点，等轮询后再填。

- 遥测/定值：电池电压、电容/操作电压、放电/充电电流、SOC、最大/当前放电时长、温度
- 遥信：A/B/C 失电、交流失电、活化/寿命监测、电池欠压、欠压切除、直流绝缘、电池容量故障、后备投入

点 **“电池参数...”** 可改容量、初始 SOC、浮充/充电/放空电压、欠压/切除阈值、
容量故障 SOC、温度；负载/充电电流仍在主界面。
参数保存到 `data/battery_config.json`（本机文件，已 gitignore）。

默认参数：48V 系统、24Ah、浮充 53.5V、充电 57.0V、欠压 46.0V、切除 43.2V。
未匹配的点保持原值；**模型不改 XML**。

DTU 的“活化启动/活化停止/放电停止/恢复出厂”遥控会同步到模型。

### 场景时间线

- **加载场景... / 开始 / 停止 / 循环**
- 步骤格式：

```json
{
  "name": "示例",
  "loop": true,
  "steps": [
    {"at": 0, "log": "初始", "set": {"0x0101": {"电池电压": 53.5}}},
    {"at": 3000, "log": "A 相失电", "set": {"0x0102": {"A 相失电告警信号": true}}},
    {"at": 5000, "group_data": {"0x1B01": "00 18 12 5C 00 28 00 64"}}
  ]
}
```

- `at` 单位毫秒；也可以写 `at_s`（秒）
- `set`：按点名设工程值，按该点的格式/系数编码
- `group_data`：直接写整组数据区 HEX
- 未匹配的组/点名、编码越界会在运行日志打 `WARN`
- 场景和电池模型互斥；示例见 `data/scenario_example.json`

## 协议行为

| 请求 | 响应 | 说明 |
|---|---|---|
| `0x01` 查询 | `0x81` | 子类型不变，数据区取对应组 |
| `0x02` 控制 | `0x82` | 1 字节结果，UI 里手动选成功/失败 |
| `0x1A` 写定值 | `0x1A` | 写入组数据区并原样回显（DTU 会逐点比较） |
| `0x1B` 读定值 | `0x1B` | 数据区取对应组 |
| `0x83` 均浮充 | `0x83` | 1 字节结果；兼容南瑞版 `0x03` 请求 |
| `0x1A/0x0C` 恢复出厂 | `0x1A` | 1 字节结果，并把所有组重置为模板/零值 |

帧格式：`EB 90 | 长度 | 地址 | 功能码 | 子类型 | 数据区 | 累加和`，
长度为 `3 + 数据区长度`，校验为从 `EB` 到数据区末尾的 8 位累加和。

## 已知限制

- 只做通用 EB90（版本 2）语义，不含福建 C1/C2、国网、上海版、专检 F30/D30 的硬编码点位差异。
- 单串口、单地址；一次加载一个装置类型表（一个完整 XML 即可包含三遥+定值）。多型号同总线时，每个型号各一份 XML；多设备/多地址后续再加。
- 静态点表：控制命令不会自动改变遥信/遥测，需要手动改。
- 故障注入只作用于响应；场景/电池模型见上一节。
- 电池模型是简化的线性电压-SOC 模型；不同电压/容量用“电池参数...”修改，保存到本机 `data/battery_config.json`。
- 电池模型的点名映射按关键字匹配；XML 点名差异大时可能匹配不到，模型日志会提示没有匹配到点。
- 场景 `set` 按点名精确匹配（含空格/大小写）；点名不一致会在运行日志打 `WARN`。
- 电池模型内部状态每秒更新，但点表只在 DTU 查询对应组时刷新；场景步骤仍按时间立即写点表。
- 正在编辑的单元格会暂缓刷新。
- 录制 0x1A/0x1B/0x83 响应依赖“20~280ms 时序 + 同功能码/子类型”判断；总线上有多个设备同时说话时可能误判，建议录制时只让目标设备应答。
- 半双工回声只做简单“300ms 内相同帧”过滤；若适配器回声严重，建议换自动方向适配器或关闭回声。
- 点格式只影响 UI 的编解码，不改 XML；类型长度必须与 `INF` 一致，否则对话框会拒绝保存。
- `data/point_formats.json`、`data/battery_config.json`、`data/preset*.json`、导出的 CSV/TXT 都是本机文件，已加入 `.gitignore`。
- 自动重连依赖 COM 名字不变；如果换了一个 COM 口，需要手动重新选择。
- 报文监视最多缓存 5000 条，导出只包含当前缓存 + 当前过滤结果。

## 常见问题

- **打不开串口**：被 SSCOM/其他程序占用；或驱动未装。
- **收到的帧一直校验错**：确认 9600 8N1、A/B 没接反、共地。
- **DTU 不轮询**：确认 DTU 的装置类型表、地址、规约版本；当前工具只应答地址匹配的请求。
- **0x1B01 没有电池容量等名称**：加载的 XML 没有 `FixValDefine`；换带定值点的 XML，或在点表的“扩展字段/原始数据”行里改。
- **中文路径**：Python/PySide6 没问题；如果以后用 PyInstaller 打包，输出目录建议用英文路径。
