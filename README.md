# 充电机模拟器 使用说明

## 1. 工具用途

在没有充电机（电源模块）实物时，用电脑 + USB-RS485 模拟一台充电机，与 DTU 进行问答通信：

- 响应 DTU 的遥测、遥信查询
- 响应遥控命令
- 响应定值读写
- 内置电池模型，模拟 SOC/电压/告警随时间变化（默认运行）

工具只做通用 EB90 规约（通用充电机/版本 2 语义），一个串口、一台设备。

---

## 2. 运行环境

- Windows 10 / 11 64 位
- USB 转 RS485 适配器（自动收发方向），并安装对应驱动
- DTU 的电源模块 485 接口（A/B）
- 打包版不需要安装 Python

接线：

```
电脑 USB-RS485 A/B  ─────  DTU 电源模块 485 A/B
电脑 USB-RS485 GND  ─────  DTU 电源模块 GND（建议共地）
```

长线建议在总线两端加 120Ω 终端电阻。

---

## 3. 快速开始（打包版）

1. 解压发布包，得到 `ChargerSim` 文件夹。
2. 双击 `ChargerSim.exe`。
3. 选择串口（USB-RS485 对应的 COM 口），波特率 9600。地址固定为 1，不需要设置。
4. 点 **“打开串口”**，顶部变成绿色 **“串口已打开”**。
5. 点 **“加载 XML...”**，选择与 DTU 配置一致的装置类型表。
6. 在“报文监视”里观察：
   - `RX`：DTU 发来的查询/控制
   - `TX`：工具回的应答
7. 左侧选择“遥测 / 遥信 / 遥控 / 定值”，查看和编辑对应数据。

> 不打开串口就不会有任何报文，这是正常的。
> 每次启动都不会自动加载上次的 XML，必须手动点“加载 XML...”选择。

## 4. 界面说明

### 顶部

| 控件 | 说明 |
|---|---|
| 串口 | 电脑 USB-RS485 适配器的 COM 口 |
| 刷新 | 重新扫描 COM 口 |
| 波特率 | 默认 9600 |
| 打开串口 | 打开后变“关闭串口”，旁边显示绿色“串口已打开” |
| 文件名 | 当前加载的 XML，悬停可看完整路径 |
| 加载 XML... | 选择装置类型表；会记住上次所在的文件夹 |
| 自动应答 | 默认勾选；取消后只收不发 |

> 设备地址固定为 1，界面不显示地址选择。

### 左侧

- **数据类型**：遥测 / 遥信 / 遥控 / 定值
  - 每类一个入口，点进去在右侧看这一类的全部点
- XML 节点计数、空节点告警（直接显示在左侧）
- **电池模型**：默认运行；交流供电、A/B/C 相失电、SOC/电压/状态、参数

### 右侧

当前分类的统一表，首列“组”表示该点来自哪个功能码/子类型。

- 顶部“点格式...”可设置数据类型
- 顶部“搜索”按名称/偏移/HEX 过滤

### 底部

- **报文监视**：只显示 `RX / TX` + 原始 HEX
  - `RX` 红色，`TX` 蓝色
  - 可按方向、HEX 文本过滤
  - 可导出 TXT 或 Markdown（时间、方向、原始帧）
- **运行日志**：XML 加载、告警、串口错误等，可导出 TXT

### 菜单

- 文件：加载 XML、保存/加载预设、重置数据、退出
- 工具：暂停应答、自动重连、点格式

## 5. 遥测 / 遥信 / 遥控 / 定值

### 遥测

- 显示：原始 HEX、原始十进制、系数、工程值
- 可直接编辑原始值或工程值
- 点“点格式...”可指定：
  - `u8/i8/u16/i16/u32/i32`、大小端、`float32`、`raw`
  - 偏移、系数

### 遥信

- 只读，不能手动改点值
- 值列显示：
  - `分`：默认，深色
  - `合`：红色加粗
- 由电池模型在 DTU 查询对应组时写入
- 左侧“遥信模拟”可按当前 XML 列出全部遥信点：
  - 勾选 = 强制该遥信为合
  - 取消 = 恢复模型自动计算
  - 仍只在 DTU 查询时写入报文

### 遥控

- 遥控是命令，不是开关状态，没有“分/合”
- 表格显示：`最后结果 / 最后时间`
- 收到遥控后记录 `成功` 或 `失败`，并更新时间
- 设备当前状态看遥信，例如“活化状态”“后备电源运行状态”
- 运行日志会记录 `收到遥控: 活化启动`

> 活化启动/停止、停止放电、绝缘测试都是独立命令；停止要用“活化停止/停止电池放电”，不是对同一个遥控点发“分”。

### 定值

- 加载 XML 后显示 `--`
- 收到 DTU 的 `0x1B/XX` 读请求后，才按协议默认值填充并显示
- 如果“电池模型 → 参数...”里给该点填了值，则用配置值覆盖协议默认值
- 收到 `0x1A/XX` 写请求时，先按协议默认值补齐再写入并解除未读
- 恢复出厂或“重置数据”后重新变回 `--`
- 协议默认值表内置在程序中，按 XML 型号选择，不依赖实物抓包
- 没有默认值的定值组，读后按 XML 长度显示原始 0

## 6. 电池模型

左侧“电池模型”**默认运行**，不需要启动、停止或重置。

- **交流供电、A/B/C 相失电**：模拟交流失电和后备放电
- **遥信模拟**：按 XML 列出全部遥信点，可强制合，用于测试各类告警
- **SOC / 电压 / 状态**：模型实时状态
- **参数...**：一页“电池参数”，内容直接来自当前装置类型表：
  - 列表只显示“名称 / 配置值”两列，不显示组、类型、系数和当前值
  - 配置值初始显示协议出厂默认值（按 XML 型号选择），遥测取电池模型当前值
  - 只有修改过的值才作为覆盖值保存；点“恢复默认”恢复初始值
  - 工具只按 XML/点格式里的系数换算，不会根据 ValueType 自动改系数；转发表换算由 DTU 侧负责
  - 遥信/遥控不在这里配置，仍由报文和模型更新

行为：

- 模型每秒更新内部 SOC/电压/告警
- **点表只在 DTU 查询对应组时才更新**；模型运行不会提前填值
- 遥测点的配置值在每次 `0x01` 查询对应组时写入
- 定值点的配置值在首次 `0x1B` 读取时写入；修改参数后，下一次 `0x1B` 重新应用
- DTU 的活化启动/停止/放电停止/恢复出厂遥控会同步到模型
- 电池容量、活化/寿命监测放电截止电压、剩余报警容量等定值会同步给内部模型，用于 SOC/告警模拟

参数保存在 `data/battery_config.json`，只保存点值配置，不再保存初始 SOC、浮充/充电/放空电压、欠压/切除、电流等模型内部参数。

## 7. 串口与无报文排查

- 串口 = **电脑上 USB-RS485 适配器的 COM 口**，不是 DTU 调试口
- 必须手动点“打开串口”
- 必须先加载 XML；未加载 XML 时点“打开串口”会提示并拒绝
- 地址固定为 1，DTU 也必须配置成 1
- XML 必须与 DTU 的装置类型表一致

正常情况：

```
每 100ms 左右出现 RX EB 90 ...
工具回 TX EB 90 ...
```

没有 RX 时：

- 选错 COM 口
- A/B 接反（对调试试）
- 没有共地
- DTU 没有轮询这个 485 口
- 驱动未装 / 端口被其他程序占用

能看到 RX 但没有 TX：

- DTU 的地址不是 1
- XML 里没有对应的组
- “自动应答”被取消，或菜单里“暂停应答”被勾选

没有连接充电机时，点表里的值是**模拟器自己的状态**，不代表真实设备。
要清零点“重置数据”。

## 10. 常见问题

**Q：启动后定值一直是 `--`？**
没有收到 `0x1B` 读定值请求。等 DTU 轮询 `0x1B01`，或在报文监视里确认是否出现 `RX ... 1B 01`。

**Q：遥信/遥控为什么不能改？**
遥信表只读，要测试告警请用左侧“遥信模拟”；遥控是命令，表格只记录最后结果和时间，设备状态看遥信。

**Q：电池模型怎么启动？**
默认就在运行，没有启动/停止按钮。直接切换“交流供电”或 A/B/C 相失电即可。

**Q：电池参数里填了值，点表为什么没变？**
遥测要等 DTU 下一次 `0x01` 查询该组；定值要等下一次 `0x1B` 读取。保持默认值不会保存覆盖值，修改后才生效。

**Q：为什么没接线也有电压？**
点表是模拟器自己的状态。电池模型运行时会显示默认浮充电压；没接 DTU 只是不发报文。

**Q：报文监视没有内容？**
先确认串口已打开、A/B 接线正确、DTU 正在轮询。

**Q：exe 双击没反应？**
确认 exe 文件完整；安装 VC++ 运行库；检查杀毒软件是否拦截。

## 11. 源码运行 / 重新打包（开发者）

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install PySide6==6.12.0
.venv\Scripts\python.exe -m app.main
```

自测：

```bat
.venv\Scripts\python.exe selftest.py
```

重新打包：

```bat
build_exe.bat
```

输出：

```
dist\ChargerSim\ChargerSim.exe
dist\ChargerSim\README.md
```

发布时把整个 `dist\ChargerSim` 文件夹压缩分发即可，目标电脑无需安装 Python。
