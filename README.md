# 充电机模拟器 使用说明

## 1. 工具用途

在没有充电机（电源模块）实物时，用电脑 + USB-RS485 模拟一台充电机，与 DTU 进行问答通信：

- 响应 DTU 的遥测、遥信查询
- 响应遥控命令
- 响应定值读写
- 可选电池模型，模拟 SOC/电压/告警随时间变化

工具只做通用 EB90 规约（通用充电机/版本 2 语义），一个串口、一台设备。

---

## 2. 运行环境

- Windows 10 / 11 64 位
- USB 转 RS485 适配器（自动收发方向），并安装对应驱动
- DTU 的电源模块 485 接口（A/B）
- 打包版不需要安装 Python

接线：

```
电脑 USB-RS485 A/B  ─────  DTU 电源模块 485 A/B
电脑 USB-RS485 GND  ─────  DTU 电源模块 GND（建议共地）
```

长线建议在总线两端加 120Ω 终端电阻。

---

## 3. 快速开始（打包版）

1. 解压发布包，得到 `ChargerSim` 文件夹。
2. 双击 `ChargerSim.exe`。
3. 选择串口（USB-RS485 对应的 COM 口）、波特率 9600、地址 1。
4. 点 **“打开串口”**，顶部变成绿色 **“串口已打开”**。
5. 点 **“加载 XML...”**，选择与 DTU 配置一致的装置类型表。
6. 在“报文监视”里观察：
   - `RX`：DTU 发来的查询/控制
   - `TX`：工具回的应答
7. 左侧选择“遥测 / 遥信 / 遥控 / 定值”，查看和编辑对应数据。

> 不打开串口就不会有任何报文，这是正常的。

## 4. 界面说明

### 顶部

| 控件 | 说明 |
|---|---|
| 串口 | 电脑 USB-RS485 适配器的 COM 口 |
| 刷新 | 重新扫描 COM 口 |
| 波特率 | 默认 9600 |
| 打开串口 | 打开后变“关闭串口”，旁边显示绿色“串口已打开” |
| 地址 | 电源模块地址，默认 1 |
| 文件名 | 当前加载的 XML，悬停可看完整路径 |
| 加载 XML... | 选择装置类型表 |
| 自动应答 | 默认勾选；取消后只收不发 |

### 左侧

- **数据类型**：遥测 / 遥信 / 遥控 / 定值
  - 每类一个入口，点进去在右侧看这一类的全部点
- XML 节点计数、空节点告警、XML 检查
- **电池模型**：启动/停止/重置、活化、交流供电、A/B/C 相失电、负载/充电电流、SOC/电压/状态、电池参数

### 右侧

当前分类的统一表，首列“组”表示该点来自哪个功能码/子类型。

- 顶部“点格式...”可设置数据类型
- 顶部“搜索”按名称/偏移/HEX 过滤

### 底部

- **报文监视**：只显示 `RX / TX / ERR / ECHO` + 原始 HEX
  - 可按方向、HEX 文本过滤
  - 可导出 CSV（时间、方向、原始帧）
- **运行日志**：XML 加载、告警、串口错误等，可导出 TXT

### 菜单

- 文件：加载 XML、保存/加载预设、重置数据、退出
- 工具：暂停应答、自动重连、点格式、XML 检查、显示高级工具栏

> 故障注入、模板、录制响应默认收在“工具 → 显示高级工具栏”里。

## 5. 遥测 / 遥信 / 遥控 / 定值

### 遥测

- 显示：原始 HEX、原始十进制、系数、工程值
- 可直接编辑原始值或工程值
- 点“点格式...”可指定：
  - `u8/i8/u16/i16/u32/i32`、大小端、`float32`、`raw`
  - 偏移、系数

### 遥信

- 只读，不能手动改
- 值列显示：
  - `分`：默认，深色
  - `合`：红色加粗
- 由电池模型在 DTU 查询对应组时写入

### 遥控

- 只读，不能手动改，也没有下拉框
- 值列显示 `分 / 合`
- 收到哪条遥控报文，就把该行标成红色“合”，其余行恢复“分”
- 运行日志会记录 `收到遥控: 活化启动`
- 恢复出厂或“重置数据”后全部回到“分”

> XML 里的遥控点是命令（活化启动/停止），不是开关状态，所以用“最后收到的命令行 = 合”表示。

### 定值

- 严格按装置类型表显示，不额外生成“扩展字段”
- 加载 XML 后显示 `--`
- 收到 DTU 的 `0x1B/XX` 读请求后，才用 `data/templates.json` 填充并显示
- 收到 `0x1A/XX` 写请求时，先按模板补齐再写入并解除未读
- 恢复出厂或“重置数据”后重新变回 `--`
- 没有模板的定值组，读后按 XML 长度显示原始 0

> `0x1B01` 在你的 DTU 上是周期轮询（约 4~5 秒一次），所以打开串口后很快会显示定值；
> 其他定值组可能只在主站读对应组时才出现。

## 6. 电池模型

左侧“电池模型”区域：

- **启动 / 停止 / 重置**
- **活化启动 / 活化停止**
- **交流供电**、A/B/C 相失电
- **负载电流 / 充电电流**
- **SOC / 电压 / 状态**
- **参数...**：容量、初始 SOC、浮充/充电/放空电压、欠压/切除阈值、容量故障 SOC、温度

行为：

- 模型每秒更新内部 SOC/电压/告警
- **点表只在 DTU 查询对应组时才更新**；启动模型不会提前填值
- DTU 的活化启动/停止/放电停止/恢复出厂遥控会同步到模型

默认参数：48V 系统、24Ah、浮充 53.5V、充电 57.0V、欠压 46.0V、切除 43.2V。
参数保存在 `data/battery_config.json`。

## 7. 串口与无报文排查

- 串口 = **电脑上 USB-RS485 适配器的 COM 口**，不是 DTU 调试口
- 必须手动点“打开串口”
- 地址默认 1，必须与 DTU 配置一致
- XML 必须与 DTU 的装置类型表一致

正常情况：

```
每 100ms 左右出现 RX EB 90 ...
工具回 TX EB 90 ...
```

没有 RX 时：

- 选错 COM 口
- A/B 接反（对调试试）
- 没有共地
- DTU 没有轮询这个 485 口
- 驱动未装 / 端口被其他程序占用

能看到 RX 但没有 TX：

- 地址不一致
- XML 里没有对应的组
- “自动应答”被取消，或菜单里“暂停应答”被勾选
- 高级工具栏里“不回帧”被勾选

没有连接充电机时，点表里的值是**模拟器自己的状态**，不代表真实设备。
要清零先停止电池模型，再点“重置数据”。

## 8. 预设 / 模板 / 高级工具栏

- **预设**：文件菜单保存/加载 JSON，可一键恢复一组测试值
- **模板**：`data/templates.json` 给没有真实报文的组提供响应数据
  - 模板只影响响应帧，不会在点表增加扩展字段
- **高级工具栏**：工具菜单显示后，可找到故障注入、模板管理、录制响应

`data` 文件夹必须与 `ChargerSim.exe` 同级。

## 10. 常见问题

**Q：启动后定值一直是 `--`？**
没有收到 `0x1B` 读定值请求。等 DTU 轮询 `0x1B01`，或在报文监视里确认是否出现 `RX ... 1B 01`。

**Q：遥信/遥控为什么不能改？**
按设计它们是读上来的状态，只能由模型/报文更新，不允许手动修改。

**Q：为什么没接线也有电压？**
点表是模拟器自己的状态。电池模型运行时会显示默认浮充电压；没接 DTU 只是不发报文。

**Q：报文监视没有内容？**
先确认串口已打开、A/B 接线正确、DTU 正在轮询。

**Q：exe 双击没反应？**
确认 `data` 文件夹与 exe 同级；安装 VC++ 运行库；检查杀毒软件是否拦截。

## 11. 源码运行 / 重新打包（开发者）

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install PySide6==6.12.0
.venv\Scripts\python.exe -m app.main
```

自测：

```bat
.venv\Scripts\python.exe selftest.py
```

重新打包：

```bat
build_exe.bat
```

输出：

```
dist\ChargerSim\ChargerSim.exe
dist\ChargerSim\data\templates.json
```

发布时把整个 `dist\ChargerSim` 文件夹压缩分发即可，目标电脑无需安装 Python。
