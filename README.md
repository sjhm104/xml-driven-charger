# 充电机模拟器（EB90 通用规约）

在没有充电机实物时，用 PC + USB-RS485 模拟充电机（电源模块），和 DTU 做问答测试。

- Python 3.14 + PySide6 6.12
- 只实现**通用 EB90 规约（版本 2 语义）**
- 静态点表 + 手动改值，不做电池模型/自动流程
- 支持装置类型表 XML（GB2312/GB18030）+ 组模板 JSON

## 运行

双击 `run.bat`，或者：

```bat
cd /d E:\充电机\模拟工具
.venv\Scripts\python.exe -m app.main
```

## 使用流程

1. 插好 USB-RS485，确认设备管理器里的 COM 口。
2. 选择串口、波特率（默认 9600）、地址（默认 1），点“打开串口”。
3. 点“加载 XML...”，选择装置类型表。
4. 左侧选择组，右侧修改值；下方“响应预览”显示当前组会回复的完整帧。
5. “自动应答”保持勾选；取消勾选或勾“暂停应答”后只收不发。
6. 报文监视区显示 RX/TX、解析摘要和校验结果。

## XML 支持

支持以下节点：

| 节点 | 含义 | 映射 |
|---|---|---|
| `MeasureDefine` | 遥测 | `GroupNo`=功能码，`EntryNo`=子类型，`FUN`=起始字节，`INF`=字节长度，`Factor`=系数 |
| `SignalDefine` | 遥信 | `FUN`=字节，`INF`=位号 |
| `ControlDefine` | 遥控 | `GroupNo`/`EntryNo` 即功能码/子类型 |
| `FixValDefine` | 定值 | `FUN`=起始字节，`INF`=字节长度 |
| `SetPointDefine` | 定值（兼容） | 同上 |

每个 `(GroupNo, EntryNo)` 对应一个组，组内维护一个数据区 `bytearray`：

- 它既是点表显示的值，也是回复帧的数据区；
- XML 没有覆盖到的尾字节就是“扩展字段”，直接在“数据区 HEX”里改；
- 定值点 `ValueType` 只影响显示，**线上字节长度只按 `INF`**。

> 正常情况下，一个完整的装置类型表应同时包含 `MeasureDefine`、`SignalDefine`、
> `ControlDefine`、`FixValDefine` 全部节点，工具一次加载这一份即可。
> 当前备份里的 `WTJND.xml` 只是定值测试桩（只有 `FixValDefine` 3 点），
> `DMP2219_Pow_CQ1000WTJND.xml` 是完整三遥表但没有定值节点；
> 这是当前开发阶段的文件状态，不是工具要求。**工具不会修改 XML。**
>
> 加载后左侧显示 `遥测 x / 遥信 y / 遥控 z / 定值 w`；某个节点为 0 时，
> 报文监视会打 `WARN`，方便判断为什么 DTU 只轮询某些子类型。

## 组模板

`data/templates.json` 给没有真实报文的组提供初始数据区：

```json
{
  "0x1B01": "00 18 12 5C 00 28 00 64"
}
```

- 键支持 `0x1B01`、`1B01`、`27/1`；
- 值是十六进制字节；
- 模板比 XML 点表长的部分就是扩展字段；
- 当前 `0x1B01` 模板含义：24AH、47.00V（原始 4700）、剩余报警 40%、剩余容量 100%。

XML 里若只有 3 个定值点（`FUN=0/2/4`），第 4 个值（`FUN=6`）就从模板里保留，
UI 的“数据区 HEX”可以看到并修改。

## 协议行为

| 请求 | 响应 | 说明 |
|---|---|---|
| `0x01` 查询 | `0x81` | 子类型不变，数据区取对应组 |
| `0x02` 控制 | `0x82` | 1 字节结果，UI 里手动选成功/失败 |
| `0x1A` 写定值 | `0x1A` | 写入组数据区并原样回显（DTU 会逐点比较） |
| `0x1B` 读定值 | `0x1B` | 数据区取对应组 |
| `0x83` 均浮充 | `0x83` | 1 字节结果；兼容南瑞版 `0x03` 请求 |
| `0x1A/0x0C` 恢复出厂 | `0x1A` | 1 字节结果，并把所有组重置为模板/零值 |

帧格式：`EB 90 | 长度 | 地址 | 功能码 | 子类型 | 数据区 | 累加和`，
长度为 `3 + 数据区长度`，校验为从 `EB` 到数据区末尾的 8 位累加和。

## 自测

不需要串口和 DTU：

```bat
.venv\Scripts\python.exe selftest.py
```

会验证：

- WTJND XML 解析（组数/点数）；
- 5 组实物 `0x1B01` 响应逐字节一致；
- `0x1A01` 写入回显；
- `0x02/01` 控制、`0x01/01` 查询；
- 错误校验和识别；
- 当前 `WTJND.xml` 的 3 个定值点 + 模板扩展成 8 字节。

## 已知限制

- 只做通用 EB90（版本 2）语义，不含福建 C1/C2、国网、上海版、专检 F30/D30 的硬编码点位差异。
- 单串口、单地址；一次加载一个装置类型表（一个完整 XML 即可包含三遥+定值）。多型号同总线时，每个型号各一份 XML；多设备/多地址后续再加。
- 静态点表：控制命令不会自动改变遥信/遥测，需要手动改。
- 不做故障注入（错校验/错地址/延迟）和场景脚本。
- 半双工回声只做简单“300ms 内相同帧”过滤；若适配器回声严重，建议换自动方向适配器或关闭回声。

## 常见问题

- **打不开串口**：被 SSCOM/其他程序占用；或驱动未装。
- **收到的帧一直校验错**：确认 9600 8N1、A/B 没接反、共地。
- **DTU 不轮询**：确认 DTU 的装置类型表、地址、规约版本；当前工具只应答地址匹配的请求。
- **0x1B01 没有电池容量等名称**：加载的 XML 没有 `FixValDefine`；换带定值点的 XML，或直接在数据区 HEX 里改。
- **中文路径**：Python/PySide6 没问题；如果以后用 PyInstaller 打包，输出目录建议用英文路径。
